# WaykinLens — Spectacles Lens Studio project

**Status: SKELETON — this directory does not yet open as a Lens Studio project.**

Everything in this folder that a lens *needs* at runtime (the `.esproj`, the
scene graph, prefabs, imported assets, permission declarations, the Spectacles
Interaction Kit) can only be produced by the Lens Studio desktop editor, which
cannot run in this repository or in CI. What is committed here is the part that
*can* be reviewed and diffed as text: the adapter interfaces and the generated
TypeScript core.

---

## 1. What is here vs. what needs the editor

Committed and reviewable as text (no editor required):

- `Assets/Scripts/adapters/*.ts` — interface-only contracts for the four
  platform seams (location, audio, Lira presentation, storage). These files
  contain **no Lens Studio API imports at all**; they are pure TypeScript so
  they can be read, reviewed and diffed outside the editor.
- `Assets/Scripts/core/*.ts` — the synced copy of
  `packages/waykin-core-ts/src`, generated by
  `scripts/sync_core_ts.sh`. Never edit these by hand.
- `Assets/Scripts/presentation/*.ts`, `Assets/Scripts/demo/*.ts` — placeholders
  (`.gitkeep`) until their editor-backed implementations land.

## 4. How core sync works

One TypeScript source serves both the parity tests and the lens.

```text
packages/waykin-core-ts/src/*.ts   (source of truth, npm + node:test)
              │
              │  bash scripts/sync_core_ts.sh
              ▼
spectacles/WaykinLens/Assets/Scripts/core/*.ts   (generated, committed)
```

- Each generated file starts with the line
  `// GENERATED by scripts/sync_core_ts.sh from packages/waykin-core-ts/src — do not edit`.
  That header is the only difference from the source file.
- A full sync deletes stale `*.ts` files in the destination, so removed or
  renamed modules cannot survive as orphan copies.
- CI runs `bash scripts/sync_core_ts.sh --check`, which re-renders the core into
  a temporary directory and diffs it against the committed copy. **Any drift
  fails the build.** The fix is always the same:

  ```bash
  bash scripts/sync_core_ts.sh
  git add spectacles/WaykinLens/Assets/Scripts/core
  # commit together with the packages/waykin-core-ts/src change
  ```

- `Assets/Scripts/core/` is generated but **is committed on purpose** — removing
  it from git would break `--check` and would make the lens unbuildable from a
  fresh clone.
- Never put a Lens Studio API import inside `packages/waykin-core-ts/src`: the
  package's isolation check (`npm run isolation`) rejects it, and the synced
  copy would then fail to compile outside the editor.

## 5. Adapter ownership rule

Every file in `Assets/Scripts/adapters/` is a header + an interface. If you feel
the urge to add logic there, put it in one of these places instead:

- pure/derivable logic → `packages/waykin-core-ts/src` (then re-sync), or
- Lens Studio-backed implementation → a new editor-only file next to the
  adapter (e.g. `LocationAdapter.lens.ts`), which is where the Lens APIs,
  `TODO(editor)` work and the scene wiring live.
